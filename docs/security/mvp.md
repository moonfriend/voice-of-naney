# Security & privacy notes — MVP

What the design protects, how, and what is knowingly left open.

## Secrets
- All credentials sit in `../naney-secrets/` (`chmod 700`), outside the git tree. `.gitignore`
  blocks env/key files as a second line of defence.
- **Public:** the Flutter app contains only publishable values (Supabase URL and publishable key,
  MapTiler key, API URL).
- **Server-only:** the Supabase **secret** key and the R2 S3 keys are used only by the Worker
  (as encrypted Cloudflare secrets) and the local admin panel.
- Scripts pass secrets through stdin or environment variables, never argv. Error messages name
  missing keys, never values.
- CI receives no secrets.

## Accounts and roles
- Sign-ups are disabled. Every account is an invite from the local admin panel.
- `profiles.role` (`admin` | `uploader`) and `profiles.disabled` are the source of truth.
- The admin panel refuses to remove the last active admin.
- The Worker checks the user's token with Supabase Auth itself (not just its signature), so
  sessions that were signed out or deleted are rejected immediately.

## Database (row-level security)
- `anon` and `authenticated` start with **no** privileges. Each grant is explicit.
- **Visitors (`anon`)** read published recordings and their cultures and media, plus places and
  the lookup lists.
- **Uploaders**:
  - Can read their own profile and their own hidden recordings.
  - Create recordings only through `create_recording()`. That function requires consent, 1–3
    valid cultures, and verified uploads the caller owns that are not already attached to another
    recording.
  - Can edit only descriptive columns of their own recordings. They cannot change `status`,
    ownership, consent or media.
- Media revision 0 (the original) cannot be updated or deleted, even with the secret key
  (enforced by a trigger).
- The `uploads` table is readable only with the secret key.

## Uploads
- Files go straight from the browser to R2 using presigned URLs:
  - A single PUT expires after 15 minutes and is bound to the declared content type.
  - Multipart part URLs expire after 6 hours.
- The Worker enforces:
  - the allowed types, and size limits of 50 MB for audio, 500 MB for video and 10 MB for photos;
  - a daily upload limit per user (`MAX_UPLOADS_PER_DAY`, default 50).
- On completion the Worker compares the stored object's size and type with the declaration. On a
  mismatch it **deletes** the object.
- Object keys are random UUIDs generated by the Worker. Clients never choose paths.
- `/media/*` serves only keys matching that exact pattern, so path traversal is impossible.

## Personal data and location
- An origin is stored as an **area** (an OSM boundary or a drawn polygon), never a person's
  address or GPS position.
- The performer's name is optional, so performers can stay anonymous.
- Consent is required and recorded with time and user (`consent_confirmed_at`, `consent_by`).
- Place search goes through the Worker, so visitors' browsers never talk to Photon or Nominatim.
  - Only uploaders can use it.
  - Results are cached for 7 days.
  - The User-Agent identifies the app, not the person.

## Known limitations (accepted for the MVP)
- **Hidden media is not locked away:** `/media/<key>` does not check whether a recording is
  hidden. Keys are unguessable UUIDs, but anyone who already has a hidden recording's media link
  can still play it. Fix later by checking visibility in the Worker (with a short cache).
- **Created-by ids are public:** public recording rows include `created_by` and `consent_by`
  (account UUIDs, not emails). Hide them behind a view if that becomes a concern.
- **No global rate limit for geocoding:** there is no global 1 request/second throttle towards
  Nominatim, only caching and uploader-only access. That is acceptable at the expected volume; add
  a Durable Object throttle if usage grows.
- **Large files must be re-chosen:** a failed upload of a video over 100 MB requires choosing the
  file again, because browsers stream it only once.
- **Unfinished uploads:** abandoned uploads (verified but never attached to a recording) stay in
  R2. A periodic cleanup job is future work.
